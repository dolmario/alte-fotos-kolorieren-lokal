# Colourise old photos — own practice

1. Extract this full pack into a new folder. It contains an own fictional, visually monochrome photograph, an eight-node UI workflow, the equivalent API prompt, exact instruction and blank evaluation record. No model weights or claim of fresh installation or local image generation. Slight RGB differences in the input are disclosed in HERKUNFT.json.
2. Use an existing working ComfyUI installation with TextEncodeQwenImage21 and the exact available model components. Missing nodes or files are real blockers. Do not substitute similarly named families. Respect other work before starting an image run; this pack installs or downloads nothing.
3. Open or drag QWEN21-KOLORIEREN-WORKFLOW.json into the canvas. It has positioned nodes/links. QWEN21-KOLORIEREN-API.json instead belongs under the prompt field of /prompt; do not drag it as a UI graph. Actual UI import and inference acceptance of this reduced graph remain unperformed.
4. In LoadImage, upload EIGENES-SYNTHETISCHES-FOTO-SW.png. Check the preview and actual resulting filename; existing names may acquire suffixes. Preserve the original. Start with this synthetic practice rather than private family pictures.
5. Select the exact existing UNET qwen_image_2.1_int8_convrot.safetensors, CLIP qwen3vl_8b_int8_convrot.safetensors with type qwen_image, and VAE qwen_image_2.1_vae_bf16.safetensors. No enhancer or cache node is required by this reduced graph. Variant names are not compatibility guarantees for every device.
6. Follow the ten real connections: LoadImage to images.image_1; CLIP to clip; VAE to encoder vae and VAEDecode; encoder positive/negative/latent to KSampler; MODEL to KSampler; sampled LATENT to VAEDecode samples; decoded IMAGE to SaveImage.
7. Keep PROMPT.txt unchanged for the first single attempt. Start at seed11 fixed,25steps, CFG1, Euler/simple, denoise1, resolution1024. Resolution is a pixel-area budget preserving input aspect ratio, not necessarily a1024-square output. Asking to preserve identity and composition is not a fidelity guarantee.
8. Queue one run only when the device is available. Inspect errors and the actual new file. Successful API admission or a green queue is not proof of colourisation. Do not mistake an old displayed result for a new success.
9. Compare original and actual new output at full size: eyes, mouth, hands, buttons, flowers and framing. Judge added colour separately from preserved details. Save both files and fill DEIN-KOLORIERTEST.csv.
10. Change one thing at a time. A different seed or step count is a separate documented attempt. Colors are interpretations, not historically proven truth. Reject altered identity; separately verified masking/recomposition is a different workflow.
11. AMD discrete GPUs, Macs and low-VRAM devices are not automatically validated. Backend, model format and memory determine compatibility; no fresh device test claimed. Read QUELLEN.md for exact model licensing; own guide licence does not grant blanket model-use permission.
12. Optional existing-Python check: python ./PRUEFE-WORKFLOW.py --folder . --output ./my-workflow-check.json . It only checks local graph/parameters/input bytes, with no server, installation or inference. Structural success is separate from real UI and model success.
